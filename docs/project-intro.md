# 职途智行 · 项目介绍（新成员入门）

> 本文写给刚加入的同学：项目是什么、面向谁、解决了什么问题、现在做到哪一步、代码在哪、怎么跑起来。
> 所有描述以当前仓库实际代码与产品自述（小程序内「功能说明」页）为准。

---

## 一、一句话定位

**职途智行** 是一款面向大学生的 **AI 就业能力提升与生涯规划** 微信小程序：以校招合作企业的真实岗位为试点数据，帮助学生看清四件事——

**岗位要什么 → 我有什么 → 差在哪里 → 接下来怎么补。**

它把"招聘信息"和"个人经历"放进 **同一套十维能力框架** 里量化对比，产出匹配度、具体缺口和可执行的成长路线，而不是只给一句"你很匹配"。

---

## 二、面向人群

| 角色 | 痛点 | 本项目提供 |
|---|---|---|
| **在校大学生 / 应届毕业生**（核心用户） | 不知道自己适合什么岗位、简历和岗位要求对不上、不知道差在哪、不会规划大三到毕业的成长路径 | 十维能力画像、人岗匹配及具体缺口、分阶段成长计划、求职资源库 |
| **辅导员 / 学院就业指导老师**（次要用户） | 学生就业指导"一对多"，很难逐个给方案 | 学生自己填写画像即可生成可复盘的报告，老师只需点评 |
| **校招合作企业 / 学校就业服务平台**（数据侧） | 岗位信息分散、学生看不懂岗位背后的能力要求 | 把岗位原文拆解成能力要求，学生匹配后有据可依 |

> 产品边界：这是**求职准备的参考工具**，不构成任何录用承诺；也不转载政策原文，只做"来源 + 定位 + 官方链接"。

---

## 三、要解决的问题

1. **招聘信息是"岗位语言"，学生看不懂**：一段招聘启事里混着专业要求、证书、素质要求，学生很难拆解成"我该补什么"。
2. **自我认知粗糙**：学生只能凭感觉说"我沟通不错"，说不清十个维度上到底强在哪、弱在哪。
3. **匹配不透明**：常见做法只给一个"匹配度"数字，不告诉依据、不告诉缺口，学生无法行动。
4. **规划不可执行**：就业指导多是口号式建议，缺少分阶段、可勾选、可复盘的任务清单。
5. **求职信息分散**：政策文件、校招渠道、来校企业名单散落各处，且政策原文冗长、易过期。

## 四、核心能力

### 4.1 同一把尺子：十维基准

平台所有能力共用同一套能力维度，这是"匹配结果可相互对照"的前提：

**专业技能、证书要求、创新能力、学习能力、抗压能力、沟通能力、实习能力、团队协作、逻辑思维、行业认知**

> 岗位侧：分数高 = 该岗位门槛高；学生侧：分数高 = 该学生能力强。匹配时判断"学生是否达到岗位要求"，而不是比大小。

### 4.2 岗位能力画像

- 把一段招聘原文（岗位名、企业简介、行业、待遇、专业要求等）拆解成十维要求强度（0–100），并抽取岗位明确写出的 **具体技能与证书**，区分「必须 / 优先」。
- 来源如实标注：**大模型解析（DeepSeek）** 与 **本地规则解析** 分开显示，不冒充。
- 招聘信息没提到的维度标注「岗位未提要求」，**不参与后续打分**（既不抬分也不扣分），避免"要求写得越少的岗位越容易被匹配上"。

### 4.3 学生就业能力画像（核心功能）

- 入口：底部导航「能力画像」。填写三组信息：基本信息（专业/年级/意向岗位/意向行业）、能力与证书（技能、证书）、经历补充（项目/实习/获奖/成绩/自我评价）。
- 产出：十维得分与等级、**能力星球图**（十颗星球大小亮度随分变化）、**职业徽章墙**、信息完整度、综合就业竞争力。
- 两个分数要分清：**信息完整度**回答"你填了多少"，**综合竞争力**回答"按你填的内容你处在什么水平"。

### 4.4 人岗智能匹配

- 十维逐项比对，输出：综合匹配度与等级、四大类目得分（专业技能 / 证书水平 / 实践经历 / 综合素质）、十维达成度、技能与证书缺口、关键短板与提升建议。
- 设计原则（重要，评审和答辩会问）：
  - **岗位未提要求的维度不参与加权**；
  - **核心技能不达标时设总评上限**（专业技能一项都不具备，不会因为其他项满分被判"基本匹配"）；
  - **信息不足时如实降级**：可评估维度少于 3 项时，匹配度按信息完整度封顶并明确提示"岗位要求信息不足，结果仅供参考"，避免"只满足 1 项要求就显示 100%"。

### 4.5 个性化生涯发展报告

- 把前四步结果串成一条链路：职业探索与人岗匹配分析 → 职业目标与路径规划（垂直晋升 / 跨岗换路，标注平滑/可过渡/需跨领域）→ 分阶段成长计划（1–3 月 / 4–12 月 / 1 年以上）→ 评估周期与动态调整（第 1、3、6、12 个月复盘什么）。
- 支持任务勾选（本机保存）、复制导出、历史报告回看与对比；重新生成画像后报告自动按新画像重算。

### 4.6 岗位招聘

- 首页快捷入口，浏览校招合作企业岗位与企业信息；点进任一岗位可查看能力画像并直接发起人岗匹配。
- 数据来自学校就业服务平台的校招数据（同步脚本入库，可增量更新）。

### 4.7 就业政策与校招资源

- **离线可用的结构化资源库**，三个主题：就业政策（国家 / 山东省 / 聊城市）、校招企业名单（校招渠道 / 双选会 / 来校企业）、简历与面试指导。
- 每条资源带来源角标（官方文件 / 官方平台 / 媒体报道 / 平台整理）、发布机构、文号，可一键复制官方链接。
- 定位：**只给来源与定位，不转载原文、不摘录未经核对的条款数字**。

### 4.8 平台能力（知识库底座）

- **知识库**：新建/管理知识库，撰写与编辑文章，可分享、关注他人知识库；支持"我的收藏"——把资源库里收藏的政策/渠道/指导统一管理，可一键发起 AI 提问。
- **AI 助手**：围绕知识库文章内容的问答（文章挂载 → 提问 → 结构化回答），也支持直接对整库内容提问；回答可存回知识库。
- **站内搜索**：搜索知识库 / 文档 / 用户；未登录时只展示本地资源检索结果并引导登录。
- **我的**：个人中心、关注/粉丝、会员（VIP 页面）、功能说明、联系我们。

## 五、技术架构

### 5.1 前端（微信小程序）

| 技术 | 用途 |
|---|---|
| uni-app 3.0（Vue 3 + TypeScript + Vite） | 一套代码编译到微信小程序 `mp-weixin` |
| Pinia | 状态管理（知识库、用户） |
| uni-ui | 基础组件（表单、图标等） |
| uni-echarts | 能力星球图 / 雷达图 |
| 自研零依赖 Markdown 渲染 | AI 回答富文本展示（不引三方库，兼容小程序） |

- 结构：主包 4 个 tabBar 页（首页 / 能力画像 / AI 助手 / 我的）+ 知识库页，其余页面全部走**分包**（20+ 个），控制主包体积。
- API 基址统一在 `src/utils/request.ts` 的 `baseURL` 一处切换（本地 / 线上）。

### 5.2 后端

| 技术 | 用途 |
|---|---|
| Django 5.2 + DRF | REST API，JWT 认证（`Authorization: JWT <token>`） |
| Celery + Redis | 异步任务：AI 画像解析、AI 问答（提交任务 → 轮询结果） |
| PostgreSQL | 主数据库 |
| DeepSeek（OpenAI 兼容） | 学生画像解析、岗位画像解析、AI 问答 |

后端应用：

- `users` — 用户、登录、学生能力画像
- `employment` — 招聘数据、岗位画像、人岗数据接口、收藏
- `knowledge` — 知识库 / 知识节点 / 评论 / 分享 / 关注
- `ai_chat` — AI 问答任务
- `pay` — 会员
- `setsite` — 项目配置与公共组件（限流等）
- `tools` — 数据同步等运维脚本（如校招数据同步）

### 5.3 数据来源

1. **校招岗**：学校就业服务平台导出的招聘信息，由 `sync_recruitments.py` 增量同步入库（幂等去重，已同步 449 条 → 342 条唯一记录）。
2. **政策资源库**：`src/utils/careerResources.ts` 内置的结构化数据（文件名、机构、文号、官方链接），离线可用。
3. **用户内容**：知识库文章、能力画像填写内容（均由用户产生）。

## 八、本地跑起来

### 前端

```bash
pnpm install
pnpm dev:mp-weixin        # 或 npm run dev:mp-weixin，产出 dist/dev/mp-weixin
# 或用 npm run build:mp-weixin 产出 dist/build/mp-weixin
```

用**微信开发者工具**导入 `dist/dev/mp-weixin`（项目名 Comuni，`urlCheck` 已关闭）。

> 注意：没有监听进程时，改完代码需要重新 build；预览目录与构建产物要一致，否则"改了没生效"。

### 后端

```bash
# 后端目录下
.venv\Scripts\python.exe manage.py runserver 8000 --noreload

# Celery（Windows 必须 --pool=solo，没有 prefork）
.venv\Scripts\python.exe -m celery -A celery_config worker -l info --pool=solo
```

`.env` 必需项：数据库、Redis、`DEEPSEEK_API_KEY`、`SYNC_ONLINE_PASSWORD`（同步数据用）。**不要把 `.env` 提交或外发。**

## 九、协作约定

- **分支**：前端仓库 `main` 与 `branch` 两个分支保持同步推送（`git branch -f branch HEAD && git push origin branch`）；后端仓库目前**无远端**，提交仅本地。
- **提交**：一个改动一个提交，提交信息写清"改了什么 + 为什么"。
- **风格**：全站橙色主色（`#FF7239`）、不用 emoji（用单色符号/图标）、真机与开发者工具都要考虑（小程序有 hover 限制、原生组件限制）。
- **数据诚实**：不编造数字；无法确认的一律标注"信息不足/以官方为准"。

## 十、比赛视角（可写进申报材料的亮点）

1. **同一把尺子**：岗位要求与学生能力用同一套十维框架量化，匹配结果可解释、可追溯（对比"黑盒匹配度"）。
2. **反向防作弊的设计**：岗位没写要求的维度不参与打分 + 核心技能门槛 + 信息不足封顶，杜绝"要求越少越容易匹配"和"只满足一项就 100%"的误导。
3. **AI 全链路可溯源**：画像解析区分大模型/规则来源，AI 回答可引用原文核对、可存回知识库。
4. **离线资源库**：政策与校招资源离线可检索，只给来源与官方链接，规避政策时效与版权风险。
5. **知识库 × AI 联动**：笔记 → 挂载上下文 → AI 问答 → 存回知识库，形成个人求职资料闭环。
